# Steps 17–18 — real-data pipeline and the θ-parameterized SCM prior.

## 17. Data pools (`pfnfit/data.py`, `data_cache/manifest.json`)

OpenML: 6408 listed → 1253 pass filters (200–50k rows, ≤200 features, 2–10
classes, active) → 751 candidates fetched (all CC-18 members kept, 700 others
sampled) → **733 downloaded, 18 failed, 43 removed by content hash**, 690 unique.

| pool | size | use |
|---|---|---|
| `R_eval` | **50** (OpenML-CC18) | final numbers only |
| `R_dev` | **30** | every development decision |
| `R_fit` | **610** | prior fitting only |

Content hash = SHA1 of `(n, d, sorted class-count multiset, sorted column means,
sorted column sds)`, so the same underlying table under a different OpenML id
and different column names collides. A CC-18 member always wins a collision, so
`R_eval` is never weakened by dedup. Disjointness is **asserted** on both id and
hash at build time. 43/733 = 5.9% duplicates — that number goes in the paper;
without dedup, ~6% of `R_fit` would have been leakage.

Only 50 of the 72 CC-18 datasets survive (the rest exceed the row/feature/class
filters, and one was a hash duplicate). The filters are a limitation of *our*
model scale, not of the method, and must be stated as such.

## 18. The prior (`pfnfit/prior.py`), and two design errors found by testing it

`θ ∈ [0,1]^12`: depth, width, edge density, activation mix (relu / periodic /
identity / tanh / step), weight scale, propagation noise scale, noise tail
heaviness (Gaussian ↔ Student-t(2)), categorical fraction, missing rate,
monotone warp strength, label-noise rate. Class-count and feature-count laws are
**deliberately not fitted** — they are properties of the task, known at test
time, not of the inductive bias.

Implementation note that makes the whole project affordable: depth and width are
realized by **masking a fixed maximum architecture** (`L_MAX=8`, `W_MAX=64`), so
a single batched GPU kernel generates datasets with a **different θ per
dataset**. Without this, θ-conditional training would need one Python-level SCM
build per dataset per step.

### Validation gate: can a GBDT beat the majority class?
This is the cheapest possible check that the prior produces *datasets* rather
than *noise*, and it caught two errors that would have silently wasted the
entire pretraining budget.

| design | mean GBDT accuracy − majority (160 datasets) | verdict |
|---|---|---|
| v1: target = node in deepest layer, features sampled uniformly from all layers | **−0.006** | prior is noise |
| v2: target in a random layer, features weighted by layer proximity | **−0.006** | still noise; `corr(gain, width) = −0.26` |
| **v3: target = explicit function of a small observed parent set** | **+0.091** | usable |

The diagnosis in v1/v2 was that the selected features were graph **siblings** of
the target, not its **causes**. A node in the same layer shares parents with the
target but is not on a path to it, so after several noisy nonlinear hops the
mutual information is negligible — and the wider the layer, the more siblings
and the weaker each one, which is exactly the `−0.26` correlation with width.

v3 makes the construction causal and explicit: draw a target layer `tl`, draw an
in-degree `k ∈ [1,8]`, draw `k` parents from layer `tl−1`, set
`y = act(Σ_j w_j h_j) + noise`, and place each parent in the observed feature set
with probability 0.85 (so 15% of causes stay latent, giving irreducible noise).

### θ now controls difficulty in the semantically correct directions
Correlation of GBDT gain with each θ coordinate, v3:

```
catfrac  −0.19    sin      −0.14    density  −0.13
missing  −0.13    lnoise   −0.12    heavy    +0.15
depth    −0.02    width    +0.06    wscale   +0.08
```
Categorical quantization, periodic activations, missingness and label noise make
data harder; depth and width are now near-neutral, i.e. they are *structural*
knobs rather than signal destroyers. In v1/v2 depth/width dominated everything,
which is a symptom, not a feature.

### Calibration against real data — the number that says the method has room
| corpus | mean GBDT gain over majority | median | frac > 0.02 |
|---|---|---|---|
| synthetic at `θ ~ π₀` (broad) | 0.091 | — | 0.38 |
| **real `R_fit` (60 datasets)** | **0.133** | 0.096 | **0.71** |

The broad prior is systematically *harder / noisier* than real tabular data:
62% of synthetic draws are essentially unlearnable versus 29% of real ones. That
is precisely the kind of misallocation the NPMLE should correct — it should move
mass toward the learnable region — and it is a **pre-registered prediction**:

> **P1.** `π*` fitted on `R_fit` should place mass on θ with *lower* catfrac,
> lower missing rate, lower label noise and lower periodic-activation weight
> than `π₀`, and datasets drawn from `π*` should show a mean GBDT gain closer to
> 0.133 than to 0.091.

If `π*` does not move in that direction, either the prequential score is not
measuring what it should or the prior family cannot reach real data — both are
kill conditions, and P1 is checkable **before** any expensive retraining.
